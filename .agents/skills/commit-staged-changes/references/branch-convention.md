# ブランチ名規約

形式は `<種類>/<kebab-case-説明>` とします。`feature/` は使わず `feat/` に統一します。

例: `feat/add-skill`, `fix/typo-in-readme`, `docs/update-claude-md`

ブランチ名のプレフィックスは下記の一覧に限定します。コミットメッセージ規約にはあってブランチ名にはない種類（`style`・`perf`・`deps` など）は、後述の対応表に従って寄せます。

## プレフィックス一覧

| 種類 | 用途 |
|------|------|
| feat | 新機能の追加 |
| fix | バグ修正 |
| docs | ドキュメントのみの変更 |
| refactor | リファクタリング |
| chore | ビルドや補助ツールの変更 |
| test | テストの追加・修正 |
| ci | CI/CD の追加・更新 |

## コミットメッセージ規約との対応

コミットメッセージの種類は15行の対応表（`commit-convention.md`）を持ちますが、ブランチ名で使えるのは上記7種だけです。差を埋める対応は次のとおりです。

| コミットの種類 | ブランチのプレフィックス | 理由 |
|------|------|------|
| style | refactor | 振る舞いを変えないコードの変更だから。`chore` は「ビルドや補助ツールの変更」であり、ソースコードの整形は該当しない |
| perf | refactor | 外部仕様を変えずに内部を改善する変更だから |
| deps | chore | 依存の更新はビルド・ツール側の変更だから |
| remove | refactor か chore | コードを消すなら `refactor`、設定やツールを消すなら `chore` |
| merge / wip | （なし） | ブランチ名には現れない |
